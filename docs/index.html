Problem 1 · Who can see what

Every employee could see every case

What was wrong
The access rule only asked “is this person logged in?”. It never asked who they were.
What would have happened
Any salesperson could open any other salesperson’s cases. So could anyone with a login and no role at all.
What I changed
One rule per role, and nothing by default.
RoleCan read
AdminEvery case
SalesOnly the cases assigned to them
UnderwritingOnly cases still awaiting a decision
ServicingOnly funded and paid-off cases
Logged in, no roleNothing
Not logged inNothing
How you know it works
One test for each row of that table. Five of them failed before the fix; all pass now.
Problem 2 · Money math

The payoff could be off by one cent

What was wrong
The calculation used the kind of decimal number computers store only approximately. When a fee landed on exactly half a cent, it sometimes rounded up and sometimes down.
What would have happened
The code said$2,725.54
It should be$2,725.55

$2,500.50 advance at 3% a month for 3 months. The fee is $225.045. One cent is small, but a payoff letter that disagrees with the contract is not.

What I changed
The calculation now works only in whole cents, with one written rule:

The fee is rounded once, at the end, to the nearest cent, and exactly half a cent rounds up.

How you know it works
Five payoff tests with the arithmetic written out next to each. Three failed before the fix; all pass now.

What I assumed

  • I don’t know your fee model, so I used a simple example: a flat monthly fee on the original advance. If yours compounds, or has minimums or caps, the tests change but the method doesn’t.
  • I don’t know your roles. I used admin, sales, underwriting and servicing, with the simplest sensible rule for each.
  • Rounding direction is your decision, not mine. Half-up is a placeholder; it should match what your contracts say. Changing it is a one-line edit.
  • Only reading is covered. Nobody can create or edit a case through the app in this example, so those rules were out of scope.
